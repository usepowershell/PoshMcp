# Release v0.12.2

**Release Date:** May 12, 2026

## Patch (Reliability)

This release fixes a server-wide reliability hole in the out-of-process (single-host) execution path. When a PowerShell tool invocation caused the underlying `pwsh` subprocess to die — for example a native AccessViolation in a binary module, a runaway `[System.Environment]::Exit` call, or a misbehaving third-party cmdlet — every subsequent tool call would surface the same error indefinitely:

```
InvalidOperationException: OOP subprocess is not running.
```

…until the operator restarted the entire MCP server. The pool-host path already self-healed via its reconciler; the single-host path now has matching behavior.

## What changed

### Automatic subprocess recovery

`OutOfProcessCommandExecutor` now detects when its underlying `OutOfProcessHost` has died (either before the send or while a request was in flight) and transparently recovers:

1. Disposes the dead host.
2. Launches a fresh `pwsh` subprocess.
3. **Replays the cached `SetupAsync` environment configuration** — module paths, imports, install specs, startup script, repository trust, and timeout settings — so the new subprocess starts in the same state the operator configured.
4. Retries the failing invoke **exactly once**.

If the retry also fails (e.g. the user is repeatedly invoking the cmdlet that kills the host), the caller receives a real exception. The retry is not unbounded, and `cancellation` and per-request timeouts continue to apply.

### Concurrency-safe restart

Restart is serialized through an internal `SemaphoreSlim`. If a burst of concurrent in-flight invokes all observe the dead host at once, only **one** restart actually runs; the rest reuse the freshly-started host.

### Setup parameters cached on first call

`SetupAsync` now snapshots its arguments (`EnvironmentConfiguration`, `configFilePath`, setup timeout, discovery modules) so the recovery path can replay them exactly. Callers see no API change; the property is internal to the executor.

## Behavior notes

- **Errors that don't kill the host are unchanged.** In-runspace failures (parameter binding/validation, cmdlet errors, `throw` from user script) are caught by `oop-host.ps1`'s `SingleDispatcher` and reported as normal error frames. The recovery path is only triggered when the subprocess itself terminates.
- **Cancellation semantics unchanged.** Per-request `CancellationToken` and request-timeout overrides continue to abort in flight without triggering a restart.
- **Pool host unchanged.** `OutOfProcessSubprocessPool` already marked broken slots and let its reconciler replace them; that code path is untouched.

## Tests

Two new integration tests under `PoshMcp.Tests.Integration.OutOfProcessIntegrationTests`:

- **`SubprocessCrash_NextInvokeAutoRecovers`** — verifies that after the live pwsh process is force-killed, the next `InvokeAsync` succeeds against a new subprocess with a different PID.
- **`UserCommandKillsHost_NextInvokeAutoRecovers`** — generates a temporary PowerShell module whose function calls `[System.Environment]::Exit`, imports it via `SetupAsync`, invokes it (expecting failure), and then asserts that a follow-up benign invoke (`Get-Date`) succeeds against a fresh subprocess. This simulates the originally-reported failure mode (a misbehaving role-management cmdlet) end-to-end.

## Upgrade

No configuration changes are required. Drop in the new build and the recovery behavior is active for all out-of-process single-host deployments.
