# PoshMcp v0.16.3 Release Notes

**Release Date:** 2026-06-01T00:00:00Z

## Summary

v0.16.3 adds Azure Container Apps scenario infrastructure, tightens observability behavior for Application Insights-backed deployments, and narrows JWT claim diagnostics to auth-relevant safe fields. It also publishes a logging and metrics guide and removes obsolete squad automation workflows from the repository.

## What's Changed

### Azure Container Apps scenario Terraform

The new `infra/` Terraform deployment provisions a repeatable Azure Container Apps environment for PoshMcp scenario testing.

It can create or reuse a resource group, then provision shared Container Apps infrastructure including Log Analytics, Application Insights, an optional Azure Container Registry, a user-assigned managed identity, optional Azure Files storage, and one Container App per enabled scenario.

Scenarios are driven by `container_app_scenarios`, so teams can add or adjust test instances through variables instead of copying Terraform resources. The default scenario set covers basic, advanced, tenant, and observability-oriented deployments.

Terraform intentionally does not build or push container images. Build and publish the PoshMcp image before applying the deployment, then point the global or per-scenario image settings at the chosen registry image.

### Application Insights metrics behavior

Application Insights configuration is now centralized through `ApplicationInsightsConfiguration`, including support for connection strings supplied either in configuration or through `APPLICATIONINSIGHTS_CONNECTION_STRING`.

When Application Insights is enabled and a connection string is resolved, HTTP OpenTelemetry metrics use Azure Monitor without also registering the console metrics exporter. This keeps App Insights-backed HTTP deployments from duplicating metric output into container logs.

The console exporter remains the fallback when Application Insights is disabled or not fully configured.

### Safer authentication claim diagnostics

JWT token validation diagnostics now log only a small auth-relevant allowlist:

- audience (`aud`)
- scopes (`scp`, `scope`)
- roles (`roles`, `role`)
- issuer (`iss`)

The diagnostic path no longer logs arbitrary claim names or values from a validated principal. Allowed values are sanitized before structured logging so operators can still diagnose audience, scope, role, and issuer mismatches without exposing unrelated token claims.

### Doctor and observability documentation

The doctor command now has additional unit coverage for its JSON and text diagnostic sections, including environment variables, runtime settings, MCP definitions, and summary status.

The new logging and metrics guide documents PoshMcp logging providers, log levels, stdio file logging, tool invocation logging, health-check logs, log sanitization, correlation IDs, OpenTelemetry metrics, Application Insights behavior, and troubleshooting patterns.

### Repository workflow cleanup

Obsolete squad automation workflows were removed from `.github/workflows`, including old squad CI, docs, heartbeat, release, issue assignment, label enforcement, preview, promotion, triage, and label sync workflows.

## Tests

Coverage added in this release verifies:

- Application Insights configured/unconfigured detection
- environment-variable connection string fallback
- HTTP console metrics exporter suppression when Application Insights is configured
- Azure Monitor registration when Application Insights is enabled with a connection string
- no-crash behavior when Application Insights is enabled without a connection string
- safe authentication claim summaries include only allowlisted auth fields
- safe authentication claim summaries exclude identity and unsupported auth-like fields
- doctor JSON/text diagnostic sections remain present and shaped as expected

Terraform validation for the new `infra/` deployment should be run before applying infrastructure changes:

```powershell
terraform fmt -recursive
terraform init -backend=false
terraform validate
```

## Breaking Changes

None.

## Upgrade Notes

**Drop-in upgrade.** No runtime configuration migration is required for existing PoshMcp deployments.

For Azure Container Apps scenario testing, copy `infra/terraform.tfvars.example` to `infra/terraform.tfvars`, provide subscription, tenant, location, and image settings, and build/push the container image before running `terraform plan` or `terraform apply`.

For authenticated HTTP deployments, JWT validation diagnostics will show fewer claim fields by design. Use the logged audience, scope, role, and issuer values for authorization troubleshooting instead of expecting arbitrary token claims in logs.
