# PoshMcp v0.16.0 Release Notes

**Release Date:** May 28, 2026

## Summary

v0.16.0 strengthens prompt delivery by applying template rendering consistently for both file-backed and command-backed prompts, enforcing required arguments at `prompts/get` runtime, and preserving compatibility for both preferred and legacy placeholder syntax.

## What's Changed

### Prompt templating for file and command sources

`prompts/get` now renders template placeholders in content returned from both prompt sources:

- `Source: "file"` content loaded from `Path`
- `Source: "command"` output produced from `Command`

This aligns prompt rendering behavior across both source types.

### Required argument enforcement at `prompts/get`

Required prompt arguments are now validated at runtime for `prompts/get`. Requests now return `InvalidParams` when a required argument is:

- missing
- null
- whitespace-only

This closes the gap where required arguments could be declared but not enforced during retrieval.

### Placeholder compatibility: `{{argName}}` and `{argName}`

Template rendering now supports both syntaxes:

- `{{argName}}` (preferred)
- `{argName}` (backward-compatible)

This keeps existing prompt templates working while allowing a consistent preferred syntax going forward.

## Documentation

Prompt documentation was updated to reflect shipped runtime behavior and guidance:

- source-aware prompt behavior (`file` + `command`)
- runtime required-argument enforcement
- supported placeholder syntax and recommendations

## Tests

Integration coverage was expanded for prompt behavior in this release:

- template rendering validation for file-backed prompts
- template rendering validation for command-backed prompts
- required-argument error behavior (`InvalidParams`) for missing/null/whitespace values
- `prompts/list` metadata stability across `prompts/get` calls

## Breaking Changes

None.

## Upgrade Notes

**Drop-in upgrade.** No configuration changes required.

For new templates, prefer `{{argName}}`. Existing `{argName}` templates remain supported for compatibility.
