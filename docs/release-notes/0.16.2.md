# PoshMcp v0.16.2 Release Notes

**Release Date:** May 29, 2026

## Summary

v0.16.2 fixes configured command-backed MCP resources so simple command resources use the active command executor when available. This keeps `resources/read` aligned with the same module-aware execution path used by tools, while preserving the existing runspace fallback for script and pipeline resource commands.

## What's Changed

### Configured command resources use the active executor

Static/configured `McpResources` entries with `Source: "command"` and a simple command name now execute through the active `ICommandExecutor` when one is available.

This matters for deployments that load PowerShell commands through the out-of-process/module-aware executor path. Before this fix, a configured command resource could fall back to the local runspace even though the corresponding command was visible to tools through module import discovery. In that shape, `resources/read` could fail to resolve module-imported commands such as `Get-BamiTenantConfiguration`.

With this fix, simple command-backed resources follow the executor path and can see the same imported command surface as tools.

Script and pipeline command resources continue to use the runspace fallback, including commands such as:

- `'value' | Out-String`
- multi-statement scripts
- command text that requires PowerShell script parsing instead of a single command invocation

That preserves existing behavior for resource commands that are intentionally scripts rather than direct command names.

## Tests

Unit coverage now verifies that:

- simple command-backed resources invoke the configured `ICommandExecutor`
- executor-backed reads pass no parameters for configured resources
- script/pipeline command-backed resources continue to execute through the runspace fallback

## Breaking Changes

None.

## Upgrade Notes

**Drop-in upgrade.** No configuration changes required.

This patch is recommended if you expose configured MCP resources backed by module-imported PowerShell commands, especially when running with out-of-process execution. Existing file resources and script/pipeline command resources keep their current behavior.
