# PoshMcp v0.15.0 Release Notes

**Release Date:** 2026-05-19

## Summary

Spec 012 lands. PoshMcp can now derive MCP resources directly from discovered PowerShell nouns, expose them through `resources/list` and `resources/read`, and append MCP resource link blocks to successful tool results that operate on the same noun. The release is opt-in through `PowerShellConfiguration.EnableNounResources`, includes per-noun overrides, adds doctor visibility for the effective noun-resource registry, and closes the main collision and out-of-process correctness gaps found during rollout.

## What's New

### Noun-derived MCP resources (spec 012)

When noun resources are enabled, PoshMcp inspects the discovered command set and derives a readable MCP resource for each noun that has a matching `Get-{Noun}` command. Those resources are exposed with `application/json` payloads at `poshmcp://resources/{resource_name}` and are available through both stdio and HTTP hosts.

The implementation adds a dedicated noun-resource pipeline:

- `NounRegistry` builds the noun-to-resource mapping from discovered command names.
- `EffectiveNounResourceRegistry` applies overrides and suppression before the runtime surfaces are built.
- `McpNounResourceHandler` serves derived resources for `resources/list` and `resources/read`.

This keeps noun-derived resources aligned with the already-discovered tool surface instead of inventing a second discovery system.

### Per-noun overrides

`PowerShellConfiguration` now exposes:

- `EnableNounResources`
- `NounResourceOverrides`

Overrides are keyed by the default derived snake_case resource name and can:

- disable the derived resource entirely
- replace the resource name
- replace the URI
- replace the description
- suppress resource link block injection while keeping the resource readable

Configuration loading now validates override conflicts at startup so operators get an immediate failure signal instead of a silent runtime surprise.

### Tool-result resource link injection

Successful tool calls for nouns with a registered derived resource now gain an appended MCP resource block with MIME type `application/json+mcp-resource-link`. This gives MCP clients a stable handoff from "tool executed" to "resource can now be read" without modifying the tool's primary payload shape.

The link block is skipped when:

- noun resources are disabled
- the noun is suppressed by override
- the noun override sets `DisableResourceLinkBlock: true`
- the tool result is returned as an error

### Doctor: `nounResources` section

`poshmcp doctor` now reports noun-resource state directly. The new `nounResources` JSON section and matching `Noun Resources` text section show:

- whether the feature is enabled
- which derived resources were registered
- which nouns were suppressed by override
- which resource-name conflicts were detected

That makes `doctor` the canonical verification surface after enabling noun resources.

## Fixes

### Static and noun resource collision handling (#283)

The combined `resources/list` output is now de-duplicated when a static MCP resource and a noun-derived resource resolve to the same URI. Clients no longer see duplicate entries for the same effective resource identity.

### OOP execution backend guard (#289)

The noun-resource read path now enforces the intended exactly-one-backend rule in out-of-process mode, preventing ambiguous execution wiring between runspace-backed and executor-backed paths.

## Breaking Changes

None.

This is an additive, opt-in feature set. Existing deployments keep their prior resources and tool-result behavior unless `EnableNounResources` is turned on.

## Upgrade Notes

**Drop-in upgrade.** No configuration changes are required unless you want to use noun-derived resources.

If you enable the feature:

1. Set `PowerShellConfiguration.EnableNounResources` to `true`.
2. Add `NounResourceOverrides` only where you need rename, disable, URI, description, or link-injection overrides.
3. Run `poshmcp doctor` and inspect the `nounResources` / `Noun Resources` section to verify the effective registry.
