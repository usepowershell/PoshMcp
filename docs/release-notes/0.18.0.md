# PoshMcp v0.18.0 Release Notes

**Release Date:** 2026-07-17

## Summary

v0.18.0 strengthens the Streamable HTTP transport, improves HTTP session/runspace isolation and lifecycle management, and hardens out-of-process PowerShell worker recovery. It also aligns tool schemas and failures more closely with the MCP protocol.

## What's Changed

### Streamable HTTP protocol and browser security

- Updated the HTTP transport to enforce Streamable HTTP protocol negotiation for `2025-11-25` clients. After initialization, clients send the negotiated `MCP-Protocol-Version` together with `Mcp-Session-Id` on subsequent `POST`, `GET`, and `DELETE` requests.
- Retained compatibility for `2024-11-05` Streamable HTTP clients, which may omit the protocol-version header after initialization.
- Added MCP endpoint origin validation. Requests carrying an `Origin` header are accepted only when they are same-origin or match `Authentication:Cors:AllowedOrigins`.
- The deprecated HTTP-with-SSE transport is now explicitly opt-in through `McpServer:EnableLegacySse`.
- Upgraded the MCP SDK dependencies to 1.4.1.

### Safer, more predictable HTTP sessions

- HTTP MCP sessions now receive dedicated initialized PowerShell runspaces that are never shared with another session.
- Requests without `Mcp-Session-Id` run in isolated one-shot runspaces and do not retain state between requests.
- Added configurable session-runspace capacity, idle retention, sweep interval, warm-standby count, and acquisition timeout settings under `McpServer`.
- Session runspaces are released on session expiry, client `DELETE`, dynamic tool reload, and host shutdown. Releases requested while a tool is running wait for that invocation to finish.
- Warm standbys are initialized separately and are additional to assigned/leased runspace capacity.

### Tool and out-of-process reliability

- Tools with no user parameters now advertise a strict empty-object input schema.
- PowerShell command failures now surface through MCP error handling instead of being returned as serialized JSON error strings.
- Hardened cancellation, configuration reload, worker cleanup, and tracking for out-of-process PowerShell execution.

### Performance validation

- Added HTTP-session benchmark scenarios covering startup and first-session work, warm-session latency, concurrent session throughput, and bounded-capacity rejection.
- CI now verifies the benchmark contract and scenario discovery without using shared-runner timing thresholds.

## Breaking Changes

- Cross-origin browser clients that send an `Origin` header now receive `403` unless the origin is same-origin or listed in `Authentication:Cors:AllowedOrigins`.
- `2025-11-25` Streamable HTTP clients must send the negotiated `MCP-Protocol-Version` header after initialization; missing, invalid, or unsupported protocol versions receive `400`.
- Headerless HTTP calls no longer preserve PowerShell state between requests.
- Consumers that interpreted serialized `{"error": ...}` tool results must handle MCP error responses instead.

## Upgrade Notes

- For browser-based clients, add each required exact HTTPS origin to `Authentication:Cors:AllowedOrigins`; do not use wildcard origins.
- Ensure `2025-11-25` HTTP clients retain and send both `Mcp-Session-Id` and `MCP-Protocol-Version` after initialization. `2024-11-05` clients remain compatible.
- Use a session for workflows that rely on PowerShell variables or functions across calls. Configure `McpServer` session-runspace settings only when the defaults (capacity `16`, idle TTL `300` seconds, sweep interval `30` seconds, two warm standbys, and a `15`-second acquisition timeout) do not fit the deployment.
- Enable `McpServer:EnableLegacySse` only when a required legacy client cannot use Streamable HTTP.
