# PoshMcp v0.12.0 Release Notes

This release hardens the diagnostic infrastructure and expands Windows PowerShell compatibility for proxy cmdlet environments. The `doctor` command now handles startup and discovery failures gracefully, and the out-of-process executor now generates optimized cached delegates for methods with more than 16 parameters, enabling proxy cmdlets in WinPSCompat sessions to work reliably.

## What's New

### Resilient diagnostics with `poshmcp doctor` error handling

The `doctor` command now continues gracefully when PowerShell startup fails, module discovery encounters issues, or the runtime environment is partially unavailable. Rather than crashing on the first failure, diagnostics now collects available data and reports which subsystems failed to initialize — making it actionable for operators trying to debug unusual environments.

**Key improvements:**

- Handles missing or inaccessible modules without terminating the diagnostic session.
- Reports startup exceptions with context (environment, runtime version, crash point).
- Generates a complete CLI report even if some subsystems are unreachable.
- Helps operators distinguish between environmental issues (missing modules, version mismatches) and MCP server issues.

Run `poshmcp doctor` in any environment to get a complete picture of what's available and what's not.

### Windows PowerShell proxy cmdlet support via cached-delegate generation

PowerShell cmdlets that are proxies (e.g., `WinPSCompatSession` proxies wrapping Windows PowerShell cmdlets) can now be discovered and invoked reliably, even when they use more than 16 parameters. The out-of-process executor now auto-generates optimized method-invoke cached delegates for methods with >16 parameters, bypassing the .NET `MethodInfo.Invoke` reflection bottleneck.

**What changed:**

- Methods with >16 parameters are now compiled into cached IL delegates for fast invocation.
- Proxy cmdlets exposed by modules like `WindowsCompatibility` now work without hitting parameter-count reflection limits.
- No configuration required — the optimization is transparent.

**Benefit:** Enables PoshMcp to work with compatibility layers and proxy cmdlet packages that wrap older (Windows PowerShell) cmdlets, expanding the module ecosystem that can be safely exposed as MCP tools.

## Bug Fixes

- **Proxy cmdlet discovery:** Fixed method-generation failure when proxy methods exceed 16 parameters (#211).
- **Doctor startup failures:** `poshmcp doctor` no longer terminates early if PowerShell initialization encounters errors (#doctor branch).

## Improvements

- **Method invocation:** Cached-delegate generation reduces reflection overhead for high-parameter-count cmdlets.
- **Diagnostic robustness:** `doctor` command now completes with partial data instead of failing hard.
- **Integration test coverage:** New tests verify proxy cmdlet discovery, parameter count handling, and cached-delegate code paths.

## Testing

This release includes new integration tests for:

- Proxy cmdlet fixture setup and parameter enumeration.
- Method-generation for >16-parameter proxy methods.
- Cached-delegate invocation across the out-of-process boundary.
- Doctor diagnostics under discovery failure conditions.

## Breaking Changes

None. This is a backward-compatible feature and bugfix release.

## Upgrade Notes

**No configuration changes required.** Simply update PoshMcp to `v0.12.0`:

```bash
dotnet tool update -g poshmcp
```

Or pull the latest container image:

```bash
docker pull ghcr.io/usepowershell/poshmcp:latest
```

Run `poshmcp doctor` after upgrading to confirm the installation and see the complete diagnostic report, including the resolved method-generation strategy for high-parameter cmdlets.
