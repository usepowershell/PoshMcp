# PoshMcp v0.16.1 Release Notes

**Release Date:** May 29, 2026

## Summary

v0.16.1 fixes HTTP sessionless runspace selection so requests without `Mcp-Session-Id` reuse a stable default PowerShell runspace instead of creating isolated runspaces from per-request connection or trace identifiers.

## What's Changed

### Stable default runspace for sessionless HTTP requests

HTTP requests that do not include the MCP session header now use the shared `default` PowerShell runspace.

This prevents non-MCP HTTP traffic from creating unbounded isolated runspaces, including:

- health probes
- readiness checks
- incidental HTTP requests before MCP initialization
- clients that touch HTTP endpoints without an established MCP session

Before this fix, those requests could be keyed by changing connection or trace identifiers. Over time that could leave the server with many isolated runspaces and cause later MCP initialization or tool work to stall behind runspace setup and cleanup pressure.

MCP requests that include `Mcp-Session-Id` still use session-specific isolated runspaces.

## Tests

Unit coverage now verifies that:

- different MCP session IDs still create different runspaces
- the same MCP session ID reuses the same runspace
- no HTTP context uses the default runspace
- HTTP requests without `Mcp-Session-Id` reuse the same default runspace even when connection and trace identifiers differ

## Breaking Changes

None.

## Upgrade Notes

**Drop-in upgrade.** No configuration changes required.

If you run PoshMcp over Streamable HTTP behind health probes or platform readiness checks, this patch is recommended to prevent sessionless traffic from accumulating isolated PowerShell runspaces.
