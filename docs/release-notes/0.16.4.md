# PoshMcp v0.16.4 Release Notes

**Release Date:** 2026-06-02T00:00:00Z

## Summary

v0.16.4 is a patch release focused on OAuth compatibility and startup reliability. It improves Entra authorize prompt handling, aligns dynamic client registration responses with Copilot CLI expectations, and converts malformed runtime configuration JSON failures into actionable configuration errors with stable exit behavior.

## What's Changed

### OAuth authorize prompt normalization

The OAuth `/authorize` proxy now normalizes incoming `prompt` values before redirecting to Microsoft Entra.

- Unsupported prompt values (for example `create`) are stripped.
- If multiple prompt values are provided, one supported value is forwarded in priority order: `consent`, `select_account`, `login`, `none`.
- If no supported value remains, `prompt` is omitted.

This avoids Entra `AADSTS90023` failures caused by unsupported or combined prompt tokens.

### OAuth registration response compatibility

The OAuth `/register` endpoint now echoes expected dynamic client metadata fields, including `redirect_uris`, while keeping static client identity behavior.

This improves compatibility with clients that validate registration response shape, including Copilot CLI flows.

### Configuration error handling improvements

Malformed runtime JSON configuration now surfaces as a configuration error with file-path context instead of an unhandled JSON parsing exception.

CLI command handling now preserves the intended process exit behavior for configuration failures, improving startup diagnostics in container and hosted environments.

### Documentation

Updated Azure infrastructure documentation to reflect current OAuth and deployment behavior.

## Tests

This release adds or updates coverage for:

- OAuth authorize prompt normalization behavior
- OAuth registration response metadata compatibility
- transport and startup configuration error propagation behavior

## Breaking Changes

None.

## Upgrade Notes

Drop-in upgrade. No configuration schema migration is required.

If you use Entra-backed OAuth integrations, this release is recommended for more resilient client compatibility.
